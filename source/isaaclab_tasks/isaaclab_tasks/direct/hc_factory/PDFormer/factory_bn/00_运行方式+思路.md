## 1. 问题背景

产线会因为**缺料、减人、物流变慢、机台故障**等原因出现**瓶颈**（某段资源卡住，拖累整线吞吐）。

我们希望模型能同时做两件事：

1. **稠密预报**：看过去一段时间各资源的运行状态，预测**下一小段时间**每个资源的「拥堵/瓶颈分数」会不会升高。
2. **稀疏事件预报**：预测**下一次明显瓶颈事件**大概何时开始、会持续多久。

前者像「天气预报看未来一小时气温曲线」；后者像「预报下一场暴雨几点开始、下多久」。

---

## 2. 两篇论文分别在做什么

交通领域其实早就在解决类似问题，只是对象从「路口车流」换成「工厂资源」。


| 论文                                                                                          | 原问题                           | 迁移：工厂问题                                           |
| ------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------- |
| [PDFormer](https://ojs.aaai.org/index.php/AAAI/article/view/25556)（Jiang et al., AAAI 2023） | 预测路网上每个路段未来几步的**流量**（每个时刻都有数） | 预测每个资源未来窗口的 `bottleneck_score`（每个窗口都有分）           |
| [STGNPP](https://ojs.aaai.org/index.php/AAAI/article/view/26669)（Jin et al., AAAI 2023）     | 预测**下一次拥堵**何时发生、堵多久（事件很少）     | 预测**下一次瓶颈事件**何时开始、持续多久（来自 `bottleneck_event.csv`） |


要点：**两篇解决的是不同任务，不能只用其中一个。**

- 只有 PDFormer：擅长连续分数曲线  
- 只有 STGNPP：擅长事件时间，但工厂里我们还需要每个窗口、每个节点的分数，方便监控与可视化。

因此做成**双路径模型 BNPDFormer**：共享一套时空编码器，上面挂两个头。

## 3. 工厂数据

仿真跑完后，先做 Stage-C 聚合（`build_bottleneck_features.py`），得到每个 episode 的：


| 文件                         | 内容                                    |
| -------------------------- | ------------------------------------- |
| `window_feature_table.csv` | 按时间窗（如 60 秒）切好的运营特征：队列长度、占用率、阻塞/饥饿时间等 |
| `bottleneck_label.csv`     | 每个窗的瓶颈分数、是否「热窗」、未来会不会出事件等标签           |
| `bottleneck_event.csv`     | 稀疏事件表：哪台资源、从何时堵到何时                    |


模型侧再抽象成一张**资源图**：

- **节点**：机台、龙门、工人、AGV、缓冲位等（当前约 34 个）  
- **边**：工艺上下游、缓冲、物流邻接（地理邻域）  
- **特征**：每个节点每个时间窗一组运营量 + 资源类型 one-hot（**不把分数本身当输入**，避免标签泄漏）

时间设定（默认）：

- 窗长 60 秒；用过去 **12** 个窗 → 预报下一个窗的分数；  
- 事件路径看「历史已发生事件」→ 预报「下一次」间隔与时长。

## 4. 从 PDFormer 借鉴的内容

“怎么在图上、带着延迟地看邻居”


| 借鉴点              | 白话解释                 | 工厂里怎么用                           |
| ---------------- | -------------------- | -------------------------------- |
| 动态空间注意力          | 谁影响谁，会随时间变，不是死图      | 拥堵、缺料会沿产线传播，依赖关系在变               |
| Geo mask（短程）     | 只让「跳数不太远」的邻居互相看      | 工艺链、缓冲、物流上真正连着的资源                |
| Sem mask（长程）     | 行为像的节点也能互相看          | 两台工作模式相似的机台，即使物理上不挨着             |
| **DFT 延迟感知**（核心） | 看邻居时，带上「过去几步长什么样」    | 上游积压往往**晚几步**才传到下游，显式建模延迟        |
| 时间注意力 + 回归头      | 每个节点看自己的时间序列，再输出未来分数 | 用历史 12 窗预报下一窗 `bottleneck_score` |


> PDFormer 负责「连续、每个资源每个时间窗都有的瓶颈强度预报」；其中 DFT 是为了对齐工厂里常见的**延迟传播问题**

## 5. 从 STGNPP 借鉴的内容

原论文预测「下一次交通拥堵何时来、堵多久」，可以类似地迁移到瓶颈预测问题上。


| 借鉴点                      | 白话解释                          | 工厂里怎么用                                 |
| ------------------------ | ----------------------------- | -------------------------------------- |
| Spatio-temporal Inquirer | 在稠密隐状态里，按「事件发生过的位置×时间」把上下文抠出来 | 历史瓶颈事件发生在哪些资源、哪些窗，就把对应编码拿出来            |
| Continuous GRU           | 事件之间慢慢变，事件时刻猛地跳一下             | 平时缓慢积压；故障/离岗瞬间状态突变                     |
| 周期门控强度 λ                 | 强度函数带一点「时段」调制                 | 用 episode 进度当相位（订单推进到哪一阶段）             |
| **点过程 NLL + 时长误差**       | 真正按「事件时间」训练，不是只问会不会发生         | 主目标：`next_tau`（距下次多久）、`next_dur`（持续多久） |


> STGNPP 负责「稀疏、离散的瓶颈事件」：瓶颈是确定的事件，我们的模型会预测它什么时间开始，持续多久

## 6. 组合架构

入口：`factory_bn/model.py`（`BNPDFormer`）。

```text
运营特征 X  (batch × 时间窗 × 节点 × 特征)
                │
                ▼
     PDFormer 编码器
     （地理 / 语义 / 时间注意力 + DFT pattern）
                │
        ┌───────┴────────┐
        ▼                ▼
   score 预测头      事件路径（STGNPP）
   （稠密分数）         │
                       ├ Inquirer（抠历史事件上下文）
                       ├ Continuous GRU
                       └ 周期门控强度 → NLL(时间间隔) + duration
                       
                 另：辅助 will / mark / tts（数据稀疏时）
```

训练时总损失大致是：

```text
总损失 ≈ w_score × 分数回归
       + w_will  × 是否会发生（辅助）
       + w_event × 点过程 NLL（+ 时长）
```

事件极少时，总损失仍可能被 event 项抬高，但**分数头可以先训出可用基线**；事件样本上来后，NLL 才真正有区分度。

## 7. 和仿真扰动实验怎么对上

扰动在仿真侧注入（见 `03.实验设计…`），一次 run 通常只开一个维度：

- `material` / `human` / `logistics` / `machine`（或 `none` 对照）  
- `intensity` 控制强弱（如 machine `2.0` 故障更久、噪声更大）

目的：让产线**真的出现可标注的瓶颈事件与分数抬升**，否则 PDFormer/STGNPP 都学不到东西。

已跑通的例子：

- `18_machine2.0`：约 50 episode、数十条瓶颈事件 → 分数 MAE≈0.17，`will` 不再塌成「永远猜没事」。  
- 早期 `15_normal` / 事件很少的 run：分数还能学，事件头指标不可信。

## 8. 怎么跑（从数据到训练）

环境用独立 conda：`bn_pdformer`（与 Isaac 仿真的 `env_isaaclab` 分开，避免驱动/依赖冲突）。

### 8.1 若还没有 `derived/`：先聚合

```bash
cd ~/work/isaac_factory

python3 source/isaaclab_tasks/isaaclab_tasks/direct/hc_factory/tools/build_bottleneck_features.py \
  --run_dir source/isaaclab_tasks/isaaclab_tasks/direct/hc_factory/output/bottleneck_dataset/18_machine2.0 \
  --window_sizes 30,60 \
  --horizon 60 \
  --score_threshold 0.55 \
  --min_event_windows 2
```

已有完整 `derived/` 可跳过。

### 8.2 导出成训练张量

```bash
conda activate bn_pdformer
cd ~/work/isaac_factory/source/isaaclab_tasks/isaaclab_tasks/direct/hc_factory/PDFormer

python -m factory_bn.export_dataset \
  --run_dir ../output/bottleneck_dataset/18_machine2.0 \
  --out_dir raw_data/FactoryBN_18_machine2.0 \
  --window_size 60
```

多 run 合并：重复传多个 `--run_dir`（episode 名会带上 run 前缀，避免冲突）。

### 8.3 训练

先在 `factory_bn/configs/FactoryBN.json` 里设好 `data_dir` / `save_dir`（避免覆盖旧实验），再：

```bash
python -m factory_bn.train \
  --config factory_bn/configs/FactoryBN.json \
  --data_dir raw_data/FactoryBN_18_machine2.0 \
  --max_epoch 100 \
  --device cuda
```

产物：


| 路径                                                   | 含义        |
| ---------------------------------------------------- | --------- |
| `libcity/cache/model_cache/<实验名>/BNPDFormer_best.pt` | 验证集最优权重   |
| `.../last_metrics.json`                              | test 指标摘要 |


长任务建议放在 `tmux` 里跑（见仓库 `07.tmux入门教程.md`）。

## 9. 指标


| 指标                   | 含义               | 注意                  |
| -------------------- | ---------------- | ------------------- |
| `score_mae`          | 预测分数与真值的平均绝对误差   | **目前最可信**的主指标之一     |
| `loss_score`         | 分数回归损失           | 应随训练下降              |
| `will_acc`           | 「未来会不会有事件」二分类准确率 | 事件很稀时会虚高（全猜「不会」也很高） |
| `loss_event` / `nll` | 点过程时间似然          | 事件少时波动大，要结合事件条数解读   |
| `dur_mae`            | 事件持续时长误差         | 事件多了才有参考价值          |

## 11. 三分钟口述稿（可直接用）

> 我们在 Isaac Lab 华测工厂仿真里注入物料/人/物流/机台扰动，采集带标签的瓶颈数据。  
> 瓶颈有两种表现：一种是每个时间窗都有的**分数**（堵得有多严重），一种是偶尔才出现的**事件**（某资源坏一段时间）。  
> 所以我们借鉴 AAAI 两篇工作：PDFormer 做稠密分数时空预报，并保留延迟感知；STGNPP 做下一次事件的时间与时长（点过程）。  
> 工程上做成共享编码器的双头模型 BNPDFormer，数据从仿真 → Stage-C 聚合 → export → train。  
> 当前在 machine 强扰动大数据集上，分数预报已到可用基线；事件头随事件样本增加才逐渐有意义。
