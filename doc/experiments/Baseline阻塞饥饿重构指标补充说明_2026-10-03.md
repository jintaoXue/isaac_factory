# Baseline 阻塞 / 饥饿时长指标补充说明（2026-10-03）

## 核对结论

`origin/dev_tyx` 最新代码新增的是独立的未来窗口重构评估：模型预测未来最多 20 个 60 秒窗口中每台设备的 `blocked_time_s` 和 `starved_time_s`，单位为每个窗口内的秒数。评估代码位于 `PDFormer/factory_bn/eval_recon_bs.py`，结果同时报告：

- 第一个未来窗口（1-step）的 MAE、RMSE；
- 所有有效未来窗口（horizon）的 MAE、RMSE；
- 真实值大于 0 的 active 窗口 MAE、RMSE；
- 1-step R²、逐预测步 MAE/RMSE；
- persistence（复制最后观测窗口）的参考误差；
- 所有监督设备、machine 子集、逐设备结果和 true-vs-pred 图表。

这些指标与已有 baseline 报告中的 `event_duration` MAE、`remain_len_mae` 或订单剩余时间 MAE 不同，不能从现有事件评估 JSON 直接换算。

## Baseline 的补充方式

当前冻结的 B3/B4/B5 事件 checkpoint 只输出事件、剩余时间和原因预测，没有 `blocked/starved` 未来序列输出。`dev_xwt` 现在的共享数据集构建器会额外保存：

- `recon_target`: 原始秒数空间的 `[sample, horizon, node, (blocked, starved)]` 目标；
- `recon_valid`: episode 结束前有效的未来步 mask。

新增 `evaluate_baseline_recon.py` 在冻结的 B3/B4/B5 encoder 上只训练一个独立的未来窗口 readout，训练只使用 train split，按 validation readout loss 选 readout，最后只在 test split 计算指标。原有 baseline 事件 checkpoint、事件指标和选模规则不被覆盖。官方主实验中的 baseline 对比范围是 B4/B5，因此本补充首先覆盖 B4/B5；B2 XGBoost 没有节点时序表征和原生序列 decoder，不能把同一 readout 直接套用到 B2。

## 服务器执行

先在 `dev_xwt` 工作区重新构建一个新的 dataset 目录（不要覆盖旧的冻结 dataset），让 `dataset.pt` 含有上述两个新字段。然后对 B4/B5 的六个冻结 `best.pt` 分别执行：

```bash
PY=/home/sci/repos/miniconda3/envs/env_isaaclab/bin/python
TOOLS=source/isaaclab_tasks/isaaclab_tasks/direct/hc_factory/tools

"$PY" -u "$TOOLS/evaluate_baseline_recon.py" evaluate \
  --dataset_dir "$DATASET_RECON" \
  --checkpoint "$CHECKPOINT" \
  --output_dir "$RECON_OUT" \
  --device cuda:0 2>&1 | tee "$RECON_OUT.log"
```

六个输出目录完成后汇总并绘图：

```bash
"$PY" -u "$TOOLS/evaluate_baseline_recon.py" summarize \
  --input_root "$RECON_ROOT"
```

每个输出目录包含 `metrics.json`、`per_device.csv`、`series.npz` 和 `readout.pt`；汇总目录包含 `summary.md`、`summary.csv` 和关键设备图。最终表格应与 `dev_tyx` 的主实验使用相同的 15 个监督设备、60 秒窗口、最多 20 步、episode 结束 mask 和 MAE/RMSE/R² 口径。
