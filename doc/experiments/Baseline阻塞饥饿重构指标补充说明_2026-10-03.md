# Baseline 瓶颈事件指标补充说明（按 dev_tyx 最新协议）

## 核对结论

`origin/dev_tyx` 最新提交（`6167a4a`）已经将主实验评估口径统一为瓶颈事件预测，不再使用此前的阻塞/饥饿重构评估脚本。`dev_xwt` 的 frozen baseline test 评估已同步这一口径，测试阶段不重新训练，也不重新选择阈值。

## 当前输出指标

- `will15_precision`、`will15_recall`、`will15_f1`：15 个监督设备的事件识别指标。
- `state_acc_1step`、`state_f1_1step`、`state_f1_horizon`：下一窗口及整个 20 窗口预测范围内的瓶颈状态栅格指标。
- `dur_mae_union`、`dur_rmse_union`：真实或预测为瓶颈的并集单元上的持续时间误差，漏报和误报分别按预测 0 或真实 0 计入。
- `dur_mae_cells`、`dur_rmse_cells`：所有有效设备单元上的持续时间误差。
- `dur_mae_tp`、`dur_rmse_tp`：正确识别事件上的持续时间误差。
- `start_mae_union`、`start_rmse_union`、`start_mae_tp`、`start_rmse_tp`：事件起始位置误差。
- `state_vs_event_acc_1step`、`state_vs_event_acc_horizon`：预测状态栅格与事件目标栅格的准确率。
- `bottleneck_per_device`：每个设备的事件数量、P/R/F1、持续时间误差和一步状态准确率。

时间单位沿用数据集的窗口单位；当前窗口为 60 秒，因此数值上等于分钟。测试报告旁边还会保存每个模型/档位的 `series.npz`，用于生成图表。

## 运行与图表

```bash
python source/isaaclab_tasks/isaaclab_tasks/direct/hc_factory/tools/summarize_frozen_baseline_test.py \\
  --report /path/to/baseline_matched_v1_test.json \\
  --output_dir /path/to/baseline_matched_v1_test_summary
```

脚本生成 `summary.csv`、`summary.md`、`per_device_best.csv`、`overview_bars.png`、`key_device_best.png` 和 `all_devices_state_best.png`。原 frozen evaluator 仍保留完整 JSON 报告，并在默认的 `<report-stem>_artifacts/` 目录写入可复用的序列文件。
