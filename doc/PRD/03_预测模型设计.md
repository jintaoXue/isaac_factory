# PRD 03：预测模型设计

## 1. 文档目的

本文档用于沉淀第三部分“预测模型设计”的当前状态、目标路线、输入输出定义、模型分阶段实现方案，以及对前两部分 PRD 的反向补充要求。

当前代码中尚未实现瓶颈预测模型训练模块。已有基础主要是：

- Isaac Sim / Isaac Lab 多智能体制造仿真环境；
- A/B/C/D 四层调度链；
- `BottleneckDataCollector` 原始日志采集；
- 瓶颈维度调研和数据采集规范；
- 完整方案中已经提出的 `PDFormer-inspired Dynamic Graph Transformer + STGNPP-style Event Head` 思路。

因此，本 PRD 的定位是：

```text
把已有研究构想转成后续可实施的模型产品需求，而不是描述当前已经完成的模型代码。
```

## 3. 预测任务定义

第三部分建议把问题定义为：

```text
给定过去 T 秒内的制造系统动态图状态，预测未来 H 秒内是否会发生瓶颈，以及瓶颈发生的位置、类型、开始时间、持续时间和严重程度。
```

形式化表达：

```text
Input:
  G_{t-T:t} = {X_{t-T:t}, E_{t-T:t}, A_{t-T:t}, U_{t-T:t}}

Output:
  y_t = {
    will_bottleneck,
    future_bottleneck_object_id,
    future_bottleneck_type,
    time_to_start,
    duration,
    severity
  }
```

其中：

- `X`：节点特征；
- `E`：边特征；
- `A`：静态/动态图邻接关系；
- `U`：全局特征；
- `T`：模型输入历史长度；
- `H`：预测未来 horizon。

## 4. 第一版时间尺度

建议第一版固定一组默认配置，后续再做 ablation。

```text
window_size = 30s
stride = 30s
input_length T = 120s
prediction_horizon H = 120s
min_bottleneck_duration = 60s
```

这样每个模型样本包含：

```text
过去 4 个窗口的图状态
预测未来 4 个窗口内的瓶颈事件
```

选择 30s 作为第一版默认窗口的原因：

- 当前 `buffer_snapshot_interval=30`；
- 30s 比 10s 稳定，噪声更低；
- 30s 又比 60s 更容易捕捉短期瓶颈迁移。

## 5. 数据输入设计

### 5.1 输入数据来源

模型不直接读取仿真原始表，而是读取离线生成的数据集。

输入链路：

```text
raw logs
  -> window_feature_table.csv
  -> graph_snapshot_table / graph_dataset
  -> model training dataset
```

当前 raw logs 包括：

```text
resource_event_log.jsonl
job_trace.csv
buffer_event_log.csv
route_transport_task.csv
material_inventory_log.csv
episode_config.csv
disturbance_log.csv
```

### 5.2 节点定义

第一版图节点建议包括：

```text
machine
gantry
human
transport_robot
buffer
material
```

暂不建议第一版把 `route` 单独建成节点。当前路径数据还不够完整，第一版可以把 route 信息作为 edge feature。

后续当 `route_id`、路径占用、交叉口等待、路径冲突等数据补齐后，再升级为：

```text
route node
route segment node
intersection node
```

### 5.3 节点特征

第一版节点特征应优先使用当前 raw logs 能稳定派生的字段。

P0 节点特征：

```text
queue_length
avg_waiting_time
occupancy_ratio
queue_growth_rate
active_pct
current_active_duration
blocked_ratio
starved_ratio
processing_time
output_rate
resource_type_embedding
```

P0 边/系统相关特征可按节点关联后写入节点输入：

```text
transport_waiting_time
route_delay
material_shortage_flag
```

P1/P2 增强特征：

```text
agent_action_count
task_selection_count
human_assignment_count
robot_assignment_count
mask_available_ratio
human_idle_duration
human_motion_speed
robot_stop_ratio
route_occupancy
edge_conflict_count
material_shortage_duration
setup_time
down_time
repair_time
tool_change_time
vision_derived_human_subtask
```

不适用某类资源的字段可以填 0，同时必须保留 `resource_type_embedding`，让模型区分字段含义。

说明：

- `blocked_time`、`starved_time`、`active_time` 与 ratio / pct 高度相关，模型输入优先使用 ratio / pct，duration 类字段主要用于解释和 severity。
- `DOWN`、`REPAIR`、`SETUP`、`TOOL_CHANGE` 当前代码没有稳定状态机，不应作为 P0。
- `human_motion_speed`、`hand_velocity` 等视觉低层特征属于 P2，不属于第一版主模型必需输入。

### 5.4 边定义

第一版建议使用三类先验边：

| 边类型 | 含义 | 来源 |

## 6. 标签设计

### 6.1 模型输出

第一版预测输出建议定义为多任务：

| 任务 | 输出 | 类型 |
|---|---|---|
| 是否发生 | `will_bottleneck` | 二分类 |
| 瓶颈位置 | `future_bottleneck_object_id` | 节点分类 |
| 瓶颈类型 | `future_bottleneck_type` | 多分类 |
| 开始时间 | `time_to_start` | 回归 |
| 持续时间 | `duration` | 回归 |
| 严重程度 | `severity` | 回归或等级分类 |

### 6.2 瓶颈类型

第一版建议瓶颈类型不要过细，先采用：

```text
machine_process_bottleneck
human_bottleneck
transport_bottleneck
buffer_bottleneck
material_bottleneck
system_congestion
```

后续扰动模块成熟后，再扩展为 root cause 级别：

```text
machine_failure
machine_slowdown
human_unavailable
transport_delay
route_congestion
material_shortage
buffer_capacity_limit
scheduling_decision
```

### 6.3 严重程度

第一版严重程度可以由窗口特征派生，不依赖反事实仿真。

建议：

```text
severity =
  normalized(bottleneck_score)
  + duration_weight
  + affected_nodes_weight
```

后续有 baseline 仿真后，可升级为：

```text
severity = throughput_loss_vs_baseline
```

### 6.4 无瓶颈样本

对于未来 horizon 内没有瓶颈事件的样本：

```text
will_bottleneck = 0
future_bottleneck_object_id = null
future_bottleneck_type = none
time_to_start = null
duration = 0
severity = 0
```

训练时只计算 occurrence loss，其他 head 需要 mask 掉。

## 7. 模型路线

### 7.1 第一阶段：非图和简单时序 baseline

第一阶段目标是验证标签和特征是否有预测信号，不追求最终模型复杂度。

建议模型：

```text
Logistic Regression / XGBoost
LSTM / GRU
TCN
```

输入可以先使用 flatten 后的窗口特征或 graph-level 聚合特征。

验收标准：

- 能跑通训练、验证、测试；
- `will_bottleneck` 的 F1 / PR-AUC 明显高于多数类 baseline；
- 能检查特征重要性，反向验证瓶颈维度是否合理。

### 7.2 第二阶段：制造图 baseline

第二阶段引入图结构。

建议模型：

```text
STGCN
DCRNN
Graph WaveNet
MTGNN
BSTAN-style GAT-GRU
```

这一阶段重点验证：

- 固定工艺图是否有效；
- adaptive graph 是否能学习隐式依赖；
- 图模型是否优于普通时序模型。

### 7.3 第三阶段：主模型

主模型采用当前完整方案中的路线：

```text
Prior-guided Delay-aware Dynamic Spatio-Temporal Graph Transformer
+ STGNPP-style Multi-task Event Head
```

结构：

```text
Graph sequence G_{t-T:t}
  -> Node / Edge / Global Feature Encoder
  -> Prior-guided Dynamic Graph Construction
  -> Delay-aware Dynamic Spatio-Temporal Transformer Encoder
  -> Multi-task Event Head
  -> Future bottleneck event prediction
```

主模型需要体现三个能力：

- `Prior-guided`：使用工艺、物流、物料供应等先验图；
- `Dynamic`：引入 agent/task/resource 分配导致的动态图关系；
- `Delay-aware`：显式建模瓶颈在上下游传播的时间延迟。

## 8. 动态图设计

建议最终动态图由多源邻接矩阵组成：

```text
A_final(t) =
    alpha * A_process
  + beta  * A_transport(t)
  + gamma * A_material(t)
  + delta * A_agent(t)
  + eta   * A_learned(t)
```

第一版可先实现：

```text
A_static = A_process + A_material
A_transport(t) = route_transport_task.csv 中当前窗口活跃物流关系
A_learned(t) = adaptive adjacency
```

`A_agent(t)` 依赖 `agent_action_log.csv` 或 `agent_action_derived.csv`，因此建议放在 P1。

## 9. 损失函数

第一版多任务损失：

```text
L =
  lambda_1 * BCE(will_bottleneck)
+ lambda_2 * CE(bottleneck_node)
+ lambda_3 * CE(bottleneck_type)
+ lambda_4 * MAE(time_to_start)
+ lambda_5 * MAE(duration)
+ lambda_6 * MSE(severity)
```

对于负样本：

```text
只计算 will_bottleneck；
其余 head 使用 mask。
```

如果瓶颈样本稀疏，需要加入：

```text
class_weight
focal_loss
positive sample oversampling
episode-level balanced sampling
```

## 10. 训练与测试划分

不建议随机按窗口切分数据。相邻窗口高度相关，随机切分会造成数据泄漏。

建议切分方式：

```text
按 episode 切分
按 scenario 切分
按 policy 切分
```

第一版：

```text
Train: 70% episodes
Validation: 15% episodes
Test: 15% episodes
```

后续泛化测试：

```text
Train: rule_based + 部分扰动场景
Validation: 未见过扰动强度
Test: 未见过 policy / 未见过扰动组合
```

## 11. 评估指标

### 11.1 是否发生瓶颈

```text
Precision
Recall
F1
PR-AUC
ROC-AUC
```

瓶颈事件可能稀疏，因此 PR-AUC 比 ROC-AUC 更重要。

### 11.2 瓶颈位置

```text
Top-1 Accuracy
Top-k Accuracy
MRR
```

### 11.3 瓶颈类型

```text
Macro-F1
Weighted-F1
Confusion Matrix
```

### 11.4 时间预测

```text
MAE(time_to_start)
RMSE(time_to_start)
MAE(duration)
RMSE(duration)
```

### 11.5 事件级评估

窗口级预测还需要转换为事件级预测。

建议增加：

```text
event_precision
event_recall
event_F1
event_start_time_error
event_duration_error
```

## 12. 实验设计

第一版实验顺序：

```text
1. rule_based 生成数据
2. 生成 window_feature_table / bottleneck_label / bottleneck_event
3. 训练 XGBoost / LSTM / TCN baseline
4. 训练 STGCN / Graph WaveNet / MTGNN baseline
5. 训练主模型简化版
6. 做 ablation
```

核心消融：

```text
去掉 graph structure
去掉 A_transport(t)
去掉 A_learned(t)
去掉 agent action features
去掉 delay-aware module
不同 window_size / horizon
不同 bottleneck_score 权重
```
